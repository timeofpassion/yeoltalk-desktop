# 슬랙 0.1.2 — 통합 창·알림 숫자

- 2026-10-30 이선주 신고: 작업표시줄4개가 어느 대화인지 찾기 어려움. 정상 설치·실행 회신은 별도 확인.
- 코드상 결함: `slackUnread || unread`로 한쪽만 집계, Windows 미지원 `app.setBadgeCount`만 호출, 숫자별 방 메뉴 없음. 본문 작은창 링크가 큰 창을 /talk로 바꾸는 경로도 수정.
- 서버 숨김 헤더의 전역 웹 배지 설정은 별도 PR에서 중단. 선주 화면의 정확한4개와 원인별1:1 대조는 직원 회신 전이다. 신고 당시 일반 알림 현재 수와는 일치하지 않으므로4개 출처를 확정하지 않는다.
- 통합 요청 반영: 앱·창·바로가기 이름은 「슬랙」. 별도 열톡 창·메뉴를 없애고 `/talk`·`/talk/<방>` 링크를 같은 슬랙 창으로 연결한다. 방·쿼리·스레드 정보를 유지하며 최소 창 폭은360px이다. 기존 별도 열톡의 설치·프로필·업데이트 피드는 건드리지 않는다.
- 자동검사20개 통과(기존17개 동작 검사+옛 링크3개). 통합 변경 및 후속 thread→m 변경 전 관련 기대값3건 실패를 각각 확인하고 수정했다. 합산2+2=4·읽은 뒤0·세션만료·음소거 멘션·대화 경로·위험URL·자동 업데이트 검증 유지. 반복 프로필 조회는5분 간격/5초 제한/배지 선갱신 유지.
- `scripts/verify-inbox-runtime.cjs`: 실제 Electron 메인/메뉴/Windows overlay 이미지/HTTPS 요청 훅을 격리 데이터로 실행, 종료0. 4개→방 열기→옛 열톡 팝업/직접주소가 같은 슬랙 창의 같은 방으로 이동→`thread`를 서버UI가 읽는 `m`으로 변환·기존 `m` 우선→최종URL과 격리 렌더러가 읽은 메시지값 확인→보조 창/메뉴 없음→읽음POST→배지/방 메뉴0→인증만료 메뉴 비우기 통과. 최신 실행의 격리 창 캡처 성공. 실제 직원 로그인·작업표시줄 고정 상태·새 서버UI의 육안 검증은 아님.
- NSIS 제작 종료0. thread→m 수정 후 최신 로컬 검토본123690243바이트, SHA256 `68F11FB929C634E1C360D916919B58FE6F9889B6BF5CCBA2E26599E192E142A0`. asar324파일 중 메인·규칙·프리로드·업데이트 파일 원본일치, 패키지 표시이름 슬랙·사용자 로그인 프로필 미포함 확인. 최신 패키지에서 추출한 규칙으로 /talk/room123?thread=msg1→/slack?c=room123&m=msg1 확인. 공식 CI 릴리스·NAS 교체 전. 버전은 아직 미출시인0.1.2 유지.
- 격리 시험 쿠키를 저장→프로세스 종료→재실행해서 유지 확인(실제 회사 로그인 아님). 실제 새 설치파일을 로컬 시험 업데이트 서버에서 다운로드, SHA512 원본일치 확인. 설치 실행·운영 업데이트 피드 검증·직원PC 설치는 하지 않았다.
- 실제 외부 Slack과 내부 운영 웹을 Aside에서 열어 채널/작성기/내 활동(DM·멘션·스레드)/검색 동선을 관찰. 모든 기능의 전수 비교 통과나 검색 결과 전수 일치 검증으로 보고하지 않는다.
- 남음: 직원PC 재현/재검증, Windows 고정 아이콘 육안, 키워드·팔로우 스레드 등 외부 Slack 알림 정책 호환, 푸시/첨부/IME/재시작 실기기 종합 확인. 토요일 점검으로 인계.
- 서버 권한 경계는 변경하지 않음. 옛 /talk/<방>은 같은 /slack?c=<방>으로 이동하고 서버의 참여 권한 검사를 따른다. 별도 열톡의 쿠키를 복사하거나 기존 설치를 삭제하지 않는다. 설치 전에 기존 열톡을 종료하고 각 직원이 본인 계정으로 로그인하도록README에 명시했다.
