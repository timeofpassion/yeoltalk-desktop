# 슬랙 Windows 설치 프로그램

Windows 10/11 64비트용. `/slack`을 독립 창으로 열고 같은 계정·같은 대화·파일을 사용한다.
앱 안에서 홈·DM·베스타·활동·검색을 함께 쓴다. 기존 열톡 앱과 프로그램 ID·프로필·설치 경로·업데이트 피드가 다르다.

## 사용
1. 기존 열톡 프로그램이 실행 중이면 메뉴에서 종료한 뒤, 승인·공식 배포된 `passion-slack-setup-<버전>.exe` 실행 → 현재 사용자에 설치. 기존 프로그램을 자동 제거하지 않는다.
2. 바탕화면 「슬랙」 → 본인 인트라넷 계정으로 로그인. 다른 PC·직원은 각자 처음 로그인한다. 직원 배포 파일에 대표의 로그인 프로필·쿠키를 넣지 않는다.
3. 창 닫기는 트레이 숨김이다. 완전 종료·업데이트 확인·자동 실행 설정은 상단/트레이 메뉴에서 한다.
4. DM·채널은 한 슬랙 창에서 연다. 기존 `/talk`·`/talk/<방>` 링크도 같은 창의 슬랙 대화로 이동한다.

## 0.1.3 비공개 첨부 다운로드(공식 반영 전)
- 새 인증 첨부의 정확한 `/api/chat/files/v1/<방>/<업로더>/<파일>` 주소만 현재 슬랙 로그인 세션으로 다운로드한다. 슬랙 창을 파일 화면으로 바꾸거나 기본 브라우저의 다른 계정으로 넘기지 않는다.
- 다른 호스트·주소 자격증명·잘못된 경로·다른 쿼리는 인증 첨부로 취급하지 않는다. 실제 파일 읽기 권한은 서버가 매 요청 현재 계정·방·메시지 범위로 확인한다.
- 프로그램 ID·개별 프로필·업데이트 피드는 유지한다. 회사 계정 쿠키·대표 프로필은 설치파일에 넣지 않는다.
- 단위검사22개와 격리 Electron 다운로드·기존 알림/옛 링크·로컬 업데이트 다운로드 검사 통과. 다운로드 시험은 운영 API 대신 같은 시험 세션의 로컬 HTTP 서버를 사용했다. 실제 직원 로그인·실물PC 설치·운영 첨부 열기·공식 업데이트 배포는 별도 확인 대상이다.
- 로컬 검토 설치파일123690317바이트, SHA256 `485819D2915E438484C85FECEA5E496B5FB4AACB28A13A4783A2782FCECC6228`. 제작 성공을 운영 배포·실기기 검증 완료로 해석하지 않는다.

## 0.1.2 통합 화면·알림 수정(공식 반영 전)
- Windows 작업표시줄 숫자를 메신저 안 읽음과 연결하고, 상단/트레이 「안 읽은 대화」에서 방별 이름·숫자를 보고 바로 연다.
- 내부 글과 슬랙 이관 글의 숫자를 합산한다. 현재 정책은 전체 안 읽음 합계이며 외부 Slack의 DM·멘션·팔로우 스레드 중심 배지와 동일하지 않다.
- 대화를 읽으면 공통 읽음 요청 완료 후 숫자를 갱신한다. 인증이 만료되면 이전 대화 메뉴·숫자를 지운다.
- 보조 열톡 창·메뉴를 제거하고 앱 이름을 「슬랙」으로 통일한다. 기존 열톡 링크의 방·쿼리·스레드 정보는 유지한다(`thread`는 슬랙이 읽는 `m`으로 변환하고 기존 `m` 우선).
- 별도 열톡 설치 프로그램과의 프로필 자동 합치기·삭제·자동실행 설정 변경은 하지 않는다. 독립 프로필·개별 로그인·URL 제한·업데이트 피드는 유지한다.
- 서버의 숨겨진 인트라넷 알림 배지 중단 수정과 함께 반영해야 한다. 검증 범위는 `검증기록-0.1.2.md` 참조.

## 0.1.1 화면·계정 범위 수정 이력
- 앱 본문에는 슬랙만 표시한다. 인트라넷 공통 메뉴(베스타·대표실·홈)와 자동 열톡 패널은 첫 표시부터 숨긴다.
- 앱 안의 페이지 이동은 슬랙·열톡·로그인으로 제한한다. 대표실·급여 등과 알 수 없는 사내 경로는 차단한다. 허용 목록의 문서·결재 링크만 기본 브라우저에서 본인 계정으로 연다.
- 당시 열톡 보조 창은 사용자가 메뉴에서 열었을 때만 표시했다. 0.1.2 통합 화면에서는 같은 슬랙 창으로 이동한다.
- 이 화면 제한은 서버 권한 검사를 대신하지 않는다. 다른 직원의 DM 접근 차단은 서버에서 별도로 검증한다.

## 업데이트
- 인트라넷 화면·업무 로직은 서버 배포 후 재실행/새로고침으로 반영된다. 작성 중 강제 새로고침은 하지 않는다.
- 프로그램은 전용 generic 피드에서 자동 다운로드, 명시적 종료/재시작 때 설치한다.
- 첫 전용 피드를 공개하기 전에는 업데이트 연결 확인 필요가 표시된다. 프로그램과 로그인은 계속 사용할 수 있다.
- 피드: `https://github.com/timeofpassion/yeoltalk-desktop/releases/download/passion-slack-updates/`
- 기존 열톡 `releases/latest`와 분리된 prerelease를 쓴다. 직원 토큰·회사 비밀번호를 배포 파일에 넣지 않는다.
- 이 PR을 main에 반영하면 전용 workflow가 테스트·설치파일 빌드·전용 prerelease 공개를 수행한다. 이후 프로그램 변경은 package.json 버전을 올려 PR→승인·머지한다. 같은/낮은 버전 재공개는 차단한다.
- 인증서가 제공되지 않아 이번 설치파일은 서명되지 않았다. Windows에서 게시자 미확인 안내가 표시될 수 있다. 보안 경고를 자동으로 해제하는 코드는 없다.

## 개발자용 근거
```powershell
npm ci --prefix apps/slack
npm test --prefix apps/slack
npm run dist --prefix apps/slack
node apps/slack/scripts/publish.cjs
```
실제 계정·직원에게 메시지를 보내는 시험은 하지 않는다. 로그인 쿠키의 재시작 유지와 실제 NSIS 파일 다운로드/해시는 격리된 Electron 런타임으로 검사한다. 다른 실물 PC 설치·회사 계정 로그인·운영 피드를 통한 설치 교체는 별도 검증 대상이다.

## 0.1.4 회사 로고 (검토용)

- 창·트레이·알림·설치·바로가기 아이콘을 인트라넷의 회사 로고 원본과 일치시킨다. PNG를 수정하지 않고 ICO 컨테이너에 포장했다.
- 앱 식별자·계정 프로필·업데이트 피드·권한 설정을 바꾸지 않는다.
- 단위 검사 22개 통과, Windows 설치 파일 제작 성공, 패키지 내부 로고와 원본 바이트 일치 확인. 공식 업데이트 공개·실제 직원 PC 설치는 하지 않았다.
- 웹 화면의 붉은 테마·열톡 DM 연결은 passion-intranet의 별도 PR이다.
