# 슬랙 PC 0.1.8 검증 기록

- 2026-11-09 대표 지시: 「주소를 벗어나면 다시 연다」 규칙을 지우고 같은 문제가 다시 생기지 않게 한다.
- 원인: 0.1.7 까지는 이동이 끝난 뒤(did-navigate·did-navigate-in-page) 주소를 보고 슬랙을 다시 불러오거나 브라우저를 열었다. 서버 주소 이동과 맞물리면 끝없이 되풀이된다(11/2 업무 화면, 11/8 옛 열톡 /talk↔/slack).
- 변경: 이동이 끝난 뒤 반응하는 처리기(navigation.cjs)를 통째로 뺐다. 판단은 이동 전에 한 번만 한다.
  - 문서 요청: 기존대로 /·/dashboard·/talk 는 요청 단계에서 슬랙으로 한 번 바꾸고, 허용 밖 주소는 취소한다(Chromium 리다이렉트 한도 20회로 끝이 있다).
  - 화면 안 이동(RSC): /·/dashboard·/talk 로 가면 취소 → Next 가 주소창 이동으로 바꿔 위 문서 요청에서 한 번만 슬랙으로 간다.
  - 업무(/tasks) 화면 안 이동은 하위 프레임(슬랙 안 업무 칸)만 허용하고, 슬랙 창 자체가 보내면 취소 → will-navigate 가 기본 브라우저로 연다.
  - 0.1.7 의 출처별 차단기(외부 열기 5회·불러오기 10회/분)는 그대로 둔다.
- 시험: `npm test` 49개 통과(이동 뒤 어떤 주소로도 다시 열지 않음, RSC 취소·하위 프레임 판정 추가).
- 실제 Electron 45(격리 시험 서버, 직원 계정·운영 데이터 없음): 업무 칸 안 RSC 허용, 슬랙 창의 업무·대시보드 RSC 취소, /dashboard 문서 요청 → /slack, 하위 프레임·상위 SPA 이동 뒤 창 재로딩 0회. 이 PC는 화면 캡처(capturePage)가 GPU 오류라 캡처만 뺀 사본으로 돌렸다.
- 설치파일 빌드·공개는 main 반영 뒤 전용 workflow 가 한다. 0.1.7 은 공개 정책을 읽고 10분 안에 받아 유휴·숨김 때 또는 30분 안에 적용한다.
