# 열정 인트라넷 통합 PC 앱 0.2.0 — 검증 및 인계

2026-11-04 대표 요청: 승인한 통합 앱 시안을 구현하고 불필요한 로딩·알림 오류를 줄인다.

## 구현
- 기존 PassionSlack 프로필과 persist:passion-slack 세션, 앱 ID를 유지한다. 대화·업무·전자결재 원본을 하나의 앱에서 전환한다.
- 최초에는 대화만 로드한다. 업무/결재는 처음 열 때 생성하며 탭 전환 시 재탐색하지 않는다. 업무 탭 닫기는 beforeunload 확인을 따른다.
- 로컬 메뉴와 원격 화면은 서로 겹치지 않는 네이티브 뷰로 구성한다. 화면을 창에 붙이고 크기를 정한 뒤 로드해야 Windows에서 첫 표시가 숨김 상태에 남지 않는다.
- 내부 업무 링크를 Next.js가 대화 화면으로 전환하기 전에 앱 탭으로 보낸다. 원격 메인 프레임의 정확한 출처·등록된 콘텐츠만 탐색 IPC를 사용할 수 있다. 범용 OS API는 노출하지 않는다.
- 받은함 요청 8초 제한, 같은 배지/메뉴 반복 생성 생략, 일시 서버 실패 시 배지 보존, 읽음 처리 중 겹친 조회 한 번 재실행. 로그아웃하면 기존 업무 뷰와 배지를 정리한다.
- 결재 업무 로직·금액 계산·DB 스키마는 변경하지 않는다. 기존 서버의 계정/권한 확인을 그대로 따른다.

## 확인 근거
- npm test: 31건 통과. 기존 첨부 이동 테스트는 workspace.test.cjs의 새 탭 컨트롤러 검사와 실제 인증 다운로드 검사로 대체.
- scripts/verify-workspace.cjs: 실제 Electron에서 격리 데이터로 40회 전환, 추가 페이지 요청 0, 대화/결재 초안 유지, 탭 닫기 후 뷰 해제. 1440/360/390px 표시·44px 버튼·가로 넘침 검사.
- scripts/verify-inbox-runtime.cjs: 실제 main.cjs 실행, 배지4→읽음0, 메뉴/방 이동, 옛 열톡 스레드 링크, 로그인 만료 목록 비우기.
- scripts/verify-private-file-runtime.cjs: 격리 세션 쿠키로 정확한 시험 파일 다운로드, 기존 창 보존, 기본 브라우저 세션 미사용.
- 디자인 검사 detect-ai-tells.mjs assets: 출력 0줄. 자체 호스팅 Pretendard, 브랜드 색상, 키보드 포커스와 버튼 이름 확인.
- Aside에서 운영 전자결재 원본을 1440/360/390px로 읽기 확인. 실제 승인·작성·서버 데이터 변경 없음. 원본 웹 확인과 설치형 앱의 실제 직원 로그인 검증은 다르다.

## 남은 단계 / 운영 상태
- PR 검토용. main 머지·공식 릴리스·자동 업데이트 피드 게시·직원 설치 모두 미실행.
- 대표 PC에서 작성 중인 내용 저장 후 설치 시험과 실제 로그인/결재 상세/첨부/알림 수신을 확인해야 한다.
- 실기기 모바일·직원 전체 환경, 장시간 사용 CPU/RAM 비교 미확인. 격리된 요청 감소 결과를 운영 체감속도 향상률로 주장하지 않는다.
- 업무 뷰를 유지하는 만큼 추가 메모리를 쓴다. 사용하지 않는 업무 탭은 닫아 해제할 수 있다.
- 웹 인트라넷 전체 알림/미확인 스레드의 업무 정책을 변경한 것이 아니다. 공유 멘션 읽음 처리 방향은 별도 대표 결정 대기다.

## 재현
작업 폴더 apps/slack에서 npm ci, npm test, npm run dist.
Electron 실행 시 ELECTRON_RUN_AS_NODE를 제거하고 각 verify 스크립트에 별도의 절대 결과 경로를 전달한다.
verify-workspace는 예시 데이터만 사용하는 검사 창을 잠시 맨 앞으로 띄워 Windows 가림 최적화와 실제 표시를 구분한다.
설치 파일과 evidence의 로컬 시험 프로필은 git에 넣지 않는다.
